# H3 Masked Split Upscale: как выбрать размер апскейла, чтобы тайлы были ровно 768

Справка для расчёта размеров. Ноды: **H3 Masked Split Upscale (tools)** и **H3 Spatial Split Params (tools)** из ComfyUI_tools. Их раскладка совпадает с MMH3 Split Upscale от LBH, поэтому расчёт подходит и к оригиналу. Все числа ниже посчитаны той же функцией раскладки, что в ноде.

## 1. Как нода режет кадр на тайлы

Работа идёт в клетках латента: 1 клетка = 16 px, а все размеры привязаны к сетке 32 px (2 клетки).

1. **Размер тайла.** `tile_width` / `tile_height` округляются до кратного 32 px: 768 → 768, 544 → 544, 500 → 512.
2. **Перекрытие:** `O = overlap_ratio × T`, округлённое до кратного 32 px. Например, при T = 768: 0.125 → 96 px, 0.25 → 192 px, 0.5 → 384 px. При 0.15 получается 115 px, это округляется до 128 px.
3. **Шаг тайлов:** `T − O`. Тайлы встают в позиции `0, шаг, 2·шаг, …`, пока не закроют кадр.
4. **Последний тайл обрезается краем кадра.** Если кадр не кратен шагу, последний тайл получается меньше T (остаток).
5. **`min_tile_size`.** Если остаток меньше этого значения, последний тайл сдвигается назад внутрь предыдущего и становится ровно `min_tile_size`. Больше T он от этого не станет.

Итог: все тайлы ровно T только при точном размере оси. Иначе остаётся маленький тайл на краю. H3 обучен на кадрах около 768 px по короткой стороне, поэтому тайлы меньше примерно 512 px сэмплируются хуже.

## 2. Формула точного размера

Все тайлы оси равны T, если размер оси

```
S = T + (n − 1) · (T − O)        n = число тайлов по оси
```

Готовые значения:

| T | overlap_ratio | O | шаг | S при n = 1, 2, 3, 4, 5 |
|---|---|---|---|---|
| 768 | 0.125 | 96 | 672 | 768, 1440, 2112, 2784, 3456 |
| 768 | 0.25 | 192 | 576 | 768, 1344, 1920, 2496, 3072 |
| 768 | 0.5 | 384 | 384 | 768, 1152, 1536, 1920, 2304 |
| 512 | 0.25 | 128 | 384 | 512, 896, 1280, 1664, 2048 |
| 1024 | 0.25 | 256 | 768 | 1024, 1792, 2560, 3328, 4096 |

`overlap_ratio` один на обе оси. Если `tile_width = tile_height`, то и перекрытие по обеим осям одинаковое, и ширину с высотой надо брать из одной строки таблицы. Чем больше перекрытие, тем мягче швы, но тем больше тайлов и дольше расчёт.

## 3. Как выбрать размер апскейла: по шагам

1. Возьми размер исходного латента в пикселях: клетки × 16. Например, H3 768P 16:9 — это 1344 × 768.
2. Выбери размер тайла T (обычно 768) и `overlap_ratio`.
3. В строке таблицы найди ширину и высоту рядом с нужным увеличением (`исходник × масштаб`) и с теми же пропорциями. Удобнее всего калькулятором из раздела 6: функция `suggest(src_w, src_h, scale)`.
4. Апскейль латент ровно в этот размер (раздел 5) и выставь в H3 Spatial Split Params тот же `tile_width`, `tile_height` и `overlap_ratio`.
5. Проверь раскладку: `tiles(ширина, T, ratio)` и `tiles(высота, T, ratio)` должны вернуть только T.

Если ровно не получается (пропорции не сходятся), есть три пути:
- **принять маленький последний тайл**, если он не меньше 512 px;
- **задать разные `tile_width` и `tile_height`**;
- **взять размер с чуть другими пропорциями** и потом обрезать.

## 4. Готовые варианты для исходника 1344 × 768 (H3 768P, 16:9)

| Цель | Размер | overlap_ratio | Тайлы по ширине × высоте | Комментарий |
|---|---|---|---|---|
| ×2 | **2688 × 1536** | **0.5** | 6 × 3, все 768 | Пропорции 1.75, ровно как у исходника. 18 тайлов, расчёт дольше всего. |
| ×2 | 2688 × 1536 | 0.25 | 768×4 + **384**, 768×2 + **384** | Мелкие краевые тайлы по 384 px, так не надо. |
| ×1.86 | 2496 × 1344 | 0.25 | 4 × 2, все 768 | Всего 8 тайлов, но пропорции 1.857: по высоте нужна подрезка. |
| ×1.43 | 1920 × 1088 | 0.25 | 768×3; по высоте 768 + **512** | Ширина ровно, по высоте остаток 512 px, это допустимо. |
| ×1.43–1.5 | 1920 × 1152 | 0.5 | 4 × 2, все 768 | Пропорции 1.667. |

**Пример неудачной раскладки.** Тайл 544 × 896 с перекрытием 0.15 на кадре 1920 × 1088 даёт по ширине `544, 544, 544, 544, 256`, по высоте `896, 320`. Краевые тайлы по 256 и 320 px для H3 слишком мелкие. Такие настройки стоит проверять функцией `tiles()` перед запуском.

## 5. Как получить точный размер латента

- **Minimax H3 Latent Upscaler (3D)** от LBH: режим **target dimensions**, `width` / `height` = размер из таблицы, `align` = 32. Получается ровно этот размер. Это рекомендуемый способ.
- **Minimax H3 Latent Upscaler (2D)** принимает только `scale`. Размер в клетках = `round(клетки × scale)` отдельно по каждой оси, и он должен выйти чётным (кратным 32 px). Подбери scale так, чтобы обе оси попали точно. Пример: 1344 × 768 → 2688 × 1536 при scale 2.0 (84 × 48 → 168 × 96 клеток). Пропорции 2D-апскейлер не меняет, поэтому вариант 2496 × 1344 им не получить.
- **VAE Encode плейта в нужном размере.** Подготовь кадры ровно в целевом размере (кратном 32) и закодируй их. Это точнее всего, если исходник есть в высоком разрешении.

## 6. Калькулятор (Python 3, без зависимостей)

```python
"""Калькулятор тайлов H3 Masked Split Upscale (та же раскладка, что в ноде)."""
import math


def _cells(px):                      # px -> клетки латента, чётное число (сетка 32 px)
    return max(2, (round(px / 16) // 2) * 2)


def _overlap(tile_cells, ratio):     # перекрытие в клетках, как в ноде
    return min(tile_cells - 2, max(0, int(round(tile_cells * ratio / 2)) * 2))


def tiles(size_px, tile_px, ratio, min_tile_px=256):
    """Размеры тайлов (px) вдоль одной оси, как их нарежет нода."""
    size, t = size_px // 16, _cells(tile_px)
    ol = _overlap(t, ratio)
    mt = min(_cells(min_tile_px), t) if min_tile_px > 0 else 0
    if size <= t:
        return [size * 16]
    step = t - ol
    n = math.ceil((size - ol) / step)
    if (n - 1) * step + t < size:
        n += 1
    starts = [i * step for i in range(n)]
    sizes = [min(t, size - s) for s in starts]
    if mt and n >= 2 and size - starts[-1] < mt and starts[-2] < size - mt < starts[-2] + sizes[-2]:
        sizes[-1] = mt
    return [s * 16 for s in sizes]


def exact_sizes(tile_px, ratio, max_tiles=8):
    """Размеры оси (px), при которых ВСЕ тайлы ровно tile_px: S = T + (n-1)(T-O)."""
    t = _cells(tile_px)
    step = t - _overlap(t, ratio)
    return [(t + (n - 1) * step) * 16 for n in range(1, max_tiles + 1)]


def suggest(src_w, src_h, scale, tile_px=768, ratios=(0.125, 0.25, 0.5), tol=0.25):
    """Точные размеры рядом с src*scale: все тайлы ровно tile_px, пропорции почти как у исходника."""
    aspect, out = src_w / src_h, []
    for r in ratios:
        sizes = exact_sizes(tile_px, r, 12)
        for w in sizes:
            for h in sizes:
                if abs(w / src_w / scale - 1) <= tol and abs(h / src_h / scale - 1) <= tol:
                    n = len(tiles(w, tile_px, r)) * len(tiles(h, tile_px, r))
                    out.append((abs(math.log(w / h / aspect)), w, h, r, n))
    for err, w, h, r, n in sorted(out)[:8]:
        print(f"{w}x{h}  overlap_ratio {r}  x{w / src_w:.3f}/{h / src_h:.3f}  "
              f"пропорции {w / h:.3f} (исходник {aspect:.3f})  тайлов {n}")


if __name__ == "__main__":
    print(tiles(1920, 768, 0.25), tiles(1088, 768, 0.25))   # [768, 768, 768] [768, 512]
    print(exact_sizes(768, 0.25, 5))                         # [768, 1344, 1920, 2496, 3072]
    suggest(1344, 768, 2.0)
```

Вывод для `suggest(1344, 768, 2.0)` начинается с:
```
2688x1536  overlap_ratio 0.5  x2.000/2.000  пропорции 1.750 (исходник 1.750)  тайлов 18
2496x1344  overlap_ratio 0.25  x1.857/1.750  пропорции 1.857 (исходник 1.750)  тайлов 8
```

## 7. Режим `tiles = around mask`: сетку можно не подбирать

В H3 Masked Split Upscale есть второй режим раскладки. Он не режет кадр сеткой, а для каждого временного чанка ставит квадрат `tile_size`×`tile_size` (по умолчанию 768) с центром на каждом белом пятне маски. Вокруг пятна внутри квадрата остаётся запас `context` (по умолчанию 128 px).

- **Положение любое, с шагом 32 px.** Квадрат прижимается к краю кадра, если пятно у края.
- **Если квадраты двух пятен перекрываются,** пятна объединяются в одно.
- **Если пятно с запасом больше квадрата,** над ним ставится маленькая сетка тайлов того же размера. Перекрытие и сглаживание берутся из H3 Spatial Split Params, если они подключены, иначе 25 % и 50 %.
- **Размер апскейла под сетку тайлов в этом режиме подбирать не нужно.** Достаточно, чтобы кадр был кратен 32 px и не меньше `tile_size`. Разделы 2–4 нужны только для режима `grid`.
- **В логе по каждому чанку видно,** где стоят квадраты: `chunk 0, frames 0-38: 1 tile(s) around the mask: 768x768 at 640,128`.

Нужна маска. Внутри одного чанка квадрат стоит на месте и накрывает весь путь объекта за чанк: объединение маски по всем кадрам чанка вместе с запасом должно уместиться в `tile_size`, то есть путь не больше `tile_size − 2·context` (512 px при настройках по умолчанию). Если больше, над путём ставится маленькая сетка.

**Длина временных чанков.** Короткие чанки уменьшают квадраты только там, где объект почти стоит на месте. На быстром движении путь за короткий чанк всё равно шире квадрата, и чанки не экономят, а добавляют квадраты и стыки по времени. Стык чанков на летящем объекте — самое заметное место для шва. Поэтому для быстро движущегося объекта обычно лучше один чанк на весь клип (без H3 Temporal Split Params или с длиной чанка не меньше клипа), даже если включится маленькая сетка. Точное число квадратов по каждому чанку показывает лог, сверяйтесь с ним.

## 8. Ещё по делу

- **Мелкие объекты (муха).** В режиме `grid` при включённом `skip_frozen_tiles` сэмплируются все тайлы, которых маска касается хотя бы в одном кадре чанка, а не только тайлы вокруг объекта в отдельном кадре. Для объекта, который сильно движется, это большая часть сетки: например, путь мухи за клип может задеть 13 из 18 тайлов раскладки 2688×1536 с перекрытием 0.5. Для мелкого объекта, который сильно движется, выгоднее `around mask` (раздел 7).
- **Временные чанки** (H3 Temporal Split Params) живут отдельно от пространственных тайлов. Их длина привязана к сетке H3: 17k + 5 кадров (22, 39, 56, 73, 90, 107, 124…).
- **Маска для ноды** — в размере кадра или в любом с теми же пропорциями (например нарисованная на плейте до апскейла). Маска переводится в клетки латента по 16 px, и значение в клетке дробное: 0 — исходник, 1 — новая генерация, 0.5 — на каждом шаге сэмплинга смесь пополам. Нода сама расширяет и растушёвывает маску до этого перевода:
  - `mask_grow` (по умолчанию 16 px) — чтобы объект целиком попал в зону 1 и полностью перерисовался, а переход лёг на фон вокруг него;
  - `mask_feather` (по умолчанию 32 px) — переход примерно через 4 клетки вместо ступеньки по сетке 16 px.

  Обе величины — в пикселях кадра латента, независимо от размера маски. Если маска уже растушёвана, ставьте `mask_feather` = 0, иначе край размоется дважды.
